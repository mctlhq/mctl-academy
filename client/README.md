# Client

The Vite + Vue + TypeScript frontend served by `../server/` (a Hono API on
PostgreSQL). Covers Practice (with per-question +1/-1 voting and reporting,
signed-in learners only), Mock exam, Review Mistakes, and a progress
dashboard, all behind GitHub/Google OAuth via better-auth. See
[`../PLAN.md`](../PLAN.md#7-application) section 7 for the full application
design and [`../README.md`](../README.md) for the project overview.

Signed out, the app still shuffles and serves questions client-side from the
static content bundle described below — sign-in only gates the
persistence-backed features (voting, attempts, mistakes, dashboard).

## Running it locally

```bash
npm ci
npm run dev     # regenerates the content bundle, then starts the Vite dev server
```

```bash
npm run build   # regenerates the content bundle, type-checks, builds to dist/
npm test        # regenerates the content bundle, then runs the Vitest suite
```

`npm run build` and `npm test` regenerate `src/content-bundle.json` and
`src/course-catalog.json` first (via `prebuild`/`pretest`), so neither is ever
stale relative to `content/`. Both are generated by
`../scripts/build-content-bundle.mjs`:

- **`content-bundle.json`** — every question eligible to be shown to a learner:
  `status: published`, human-reviewed, and citing only sources that exist, are
  snapshotted, and are neither drifted nor deprecated. Nothing in the client
  re-checks any of that at runtime, because nothing unsafe is in the file.
- **`course-catalog.json`** — the vendor-neutral course catalog derived from
  `content/courses/*.yaml`: id, title, published question count, and mock
  configuration. A course with zero published questions renders in the course
  switcher as "Coming soon" and cannot be selected; it becomes selectable the
  moment content lands for it, with no TypeScript change.

Every learning surface (Practice, Review Mistakes, Progress, Mock exam) is
scoped to the selected course by filtering the bundle on `course_id` before a
session is built.
